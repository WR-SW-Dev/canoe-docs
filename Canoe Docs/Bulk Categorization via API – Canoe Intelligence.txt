Bulk Categorization lets you correct or update document metadata for many documents
at once. Instead of updating each document individually, you can pass metadata at upload
time or update existing documents in bulk — reducing manual cleanup and keeping Canoe
aligned with your internal systems of record.
This article covers bulk updates through Canoe’s API. For making bulk changes directly in
the platform, see Bulk Categorization in the IDC. For general API guidance, see Canoe API |
Overview and Canoe API | Best Practices.

Set metadata when uploading documents
When calling PUT: Upload a Single Document, you can include the following fields:
fund_id — Sets the fund. Always applicable.
investment_entity_id — Sets the entity. Ignored for fund-level documents.
allocation_id — Sets the allocation. Ignored for fund-level documents.
data_date — Sets a single data date for the document.
document_type_id — Sets the document type. Previously limited to Storage Only; now
supports any single document type.
This call accepts up to 100 document IDs at once. All fields are optional — populate only
the ones you need.

Use PUT: Set Document Metadata to update metadata on documents that are already in
Canoe. This endpoint supports the same fields as Upload a Single Document: fund_id (or
term_id), investment_entity_id, allocation_id, data_date, and document_type_id.
The same rules apply — see the field descriptions above.
Update approval status, comments, tags, or client document ID in
bulk
Use POST: /v1/documents/metadata to update these fields for multiple documents in a
single call:
approval_status
comment
tags (with names and overwrite parameters)
client_document_id
Batch size: 1 to 100 document IDs per request. Requests exceeding 100 IDs return a 422
Validation failed error.
Tag behavior: Setting overwrite: true replaces all existing tags with the provided list.
Setting overwrite: false appends the provided tags to existing ones.
Example request
POST /v1/documents/metadata
{
  "ids": ["doc-id-1", "doc-id-2"],
  "metadata": {
    "approval_status": "approved",
    "comment": "Reviewed and approved",
    "tags": {
      "names": ["reviewed", "q1-2025"],
      "overwrite": false
    },
    "client_document_id": "CLIENT-123"
  }
}

After any API-driven metadata update, Canoe validates:
Ownership and entity/fund relationships
Required fields for each document type
Other document-type-specific rules
Document statuses update accordingly. New issues — such as ownership mismatches —
surface as exceptions. Resolved issues — such as previously missing ownership that is now
filled — allow documents to move to a complete state.
