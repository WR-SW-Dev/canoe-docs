The Gen AI Decision Tree, in plain language

A walkthrough of the firm's own tool-selection tree, plus a condensed four-question version. Include this in every architecture packet so any reviewer can trace why a given task was assigned to rules, to classic ML, or to GenAI.

The short version

Four questions, in order

The full tree has five gates, but for a gut check the first four get you 90% of the way. Read left to right; stop at the first one that answers your case.

01
Can you tell if the output is right?
No → don't reach for GenAI yet. Sharpen the task until "good" is measurable.
02
Is there one exact correct answer?
Yes → use rules, SQL, or ML. GenAI adds risk, not value.
03
Is it really about language?
No → stay with SQL / rules or a classifier. Yes → keep going.
04
Does it need our private data?
Yes → GenAI + RAG. No → standalone GenAI is enough.
The one-line takeaway

GenAI is the right tool only for open-ended language work whose quality you can still judge. Anything with a single deterministic answer belongs in rules or SQL — which, conveniently, is also cheaper, faster, and fully auditable.

The full tree, gate by gate

Why each gate exists

1
Can output quality be measured clearly?

Before choosing any tool, you need a definition of "correct." If you can't tell a good answer from a bad one, no tool can be evaluated — and GenAI's failure mode is producing confident, wrong output that looks right. This gate protects you from automating something you can't check.

NORefine the use case & restart. Define what "good" looks like first.
YESContinue to gate 2.
2
Does the task require deterministic accuracy?

"Deterministic" means the same input must always give the exact same, provably-correct answer — a totalled column, a due-date calculation, a reconciliation. This is the opposite of what a probabilistic language model is built for. If the task is deterministic, a model is the wrong instrument no matter how capable it is.

YESUse rules, SQL, or ML — avoid GenAI. Exact, fast, auditable, free of hallucination.
NOContinue to gate 3.
3
Does the task involve language generation or understanding?

GenAI's genuine edge is reading and writing natural language — messy prose, varied document formats, human phrasing. If the task isn't fundamentally linguistic, you're paying for the wrong strength.

NOUse SQL or rules-based logic. The task is structured, not linguistic.
YESContinue to gate 4.
4
Does the task require synthesis or open-ended output?

Some language tasks still have a fixed set of answers — "which of these five categories is this?" That's classification, and a smaller ML model does it more cheaply and predictably. GenAI earns its cost only when the output is genuinely open-ended: a summary, a comparison, a narrative.

NOConsider ML or classification. Fixed output space → a classifier fits better.
YESConsider GenAI — one more check below.
5
Does the task depend on proprietary enterprise knowledge?

A model only knows what it was trained on plus what you give it in the moment. If the answer depends on our documents — prior quarters, our funds, our managers — the model needs those retrieved and handed to it at request time. That pattern is RAG (Retrieval-Augmented Generation). If the task needs only general knowledge, the model can stand alone.

YESGenAI + RAG. Retrieve our own documents and ground the model on them.
NOStandalone GenAI is sufficient. General-knowledge task.
Refine / stop Rules · SQL · ML GenAI path GenAI + RAG

One honest judgment call — the extraction tasks at gate 4

Pulling a fixed set of fields (or a single date) off a document has a fixed output schema, which a literal reading of gate 4 would route to classic ML / classification. We send it to GenAI instead because the input is open-ended — GP statements arrive in wildly varying layouts, and maintaining a separate trained extractor per manager doesn't scale. The guardrail that keeps this honest is gate 1: every extracted figure is confidence-scored and validated against the prior period, and anything doubtful goes to a human. That's what makes the output measurable, which is the whole precondition for using GenAI at all.

The pattern worth noticing

Two of the five tasks — the highest-volume ones — never reach GenAI at all; they exit at gate 2 into plain SQL. GenAI is confined to the three places where the input is genuinely unstructured language, and only one of those needs our proprietary data. The expensive, repeated work stays deterministic, auditable, and free per query.
