The reference architecture

From raw document to tracked insight

The model does one narrow job — turn messy language into structured fields, once per document. Everything downstream (trends, comparisons, thresholds) is deterministic SQL against that structured data, never a fresh model call.

◆ Highlighted below — the single point where the LLM provider is configured
The dashed brass box is the only place a model is called. Swapping providers there — from in-tenant Copilot to an external API to a self-hosted model — changes nothing downstream. Model-tier selection at that node is the primary token-cost control.
Read before anything else

The compliance gate

Blocking issue — decide before building B

Wake Robin's Generative AI Chatbot Usage Policy (v1.2) lists, under Restricted Content for AI/LLM Use, data that may not be entered into any AI platform except M365 Copilot within your licensed environment:

"Financial account information, investment strategies, or portfolio details." · "Legal documents, contracts, or attorney-client privileged information."

LP statements and manager letters are financial-account and portfolio-detail documents. So sending their text to a model is not automatically cleared just because ChatGPT, Claude, Grok, and Manus appear on the authorized-platforms list — those approvals read as scoped to interactive drafting and brainstorming, not to piping restricted fund data through a pipeline.

The policy names the right path forward: "Team members may request a review of new LLMs, whether standalone or integrated into a platform, via the IT Lead/CTO." That review — not an engineering call — is what unblocks this track. The same gate applies to Architecture A's optional v2.

The two versions

Compliant path vs. better-with-approval path

Both versions share the identical architecture above; they differ only in what gets configured at the highlighted LLM node.

Version 1 · Closest to compliant

In-tenant model only (M365 Copilot / Azure OpenAI)

Configure the LLM node to the one path the policy already treats as acceptable for company financial data: a model inside the firm's licensed M365 / Azure environment. Document text never leaves the tenant.

  • Uses the policy's existing M365 Copilot carve-out
  • Narrow scope, confidence-scored, human-verified, attributed
  • Still worth confirming with IT Lead/CTO that pipeline/API use on financial docs is in scope — the written permission centers on interactive Copilot use
✔ Buildable under current policy (confirm pipeline scope)
Version 2 · Better, needs approval

Best-in-class external model under a ZDR agreement

Configure the node to a frontier external model (e.g., Claude) under a zero-data-retention enterprise agreement, secured through the policy's "request a review of a new LLM" path.

  • Higher extraction accuracy on messy, varied GP formats
  • Often lower token cost per document than in-tenant options
  • Lets the team benchmark models on cost vs. accuracy and pick per task
  • Requires formal IT Lead/CTO review + a signed ZDR / enterprise contract
▲ Requires policy review + signed data agreement
Why v2 is worth requesting

The quality of everything downstream — every trend flag, every manager comparison — is capped by how accurately figures are pulled off the page in the first place. GP statements vary enormously in layout, and a frontier model reads them materially better than a constrained in-tenant option, while a zero-data-retention agreement gives contractual assurance that the data isn't retained or trained on. Because the architecture isolates the model to one configurable node, the firm can start on v1 to prove value with zero new approvals, then switch to v2 by changing one setting the day the agreement is signed — no rework.

Minimizing token cost

The cost levers, by design

Token spend is a first-class design constraint here. The architecture is shaped so that inference cost tracks document count, not activity — and most of the "intelligence" never touches a model at all.

Extract once, never re-infer

A document is read by the model a single time on ingest. Every later question is answered from the structured warehouse with SQL — free.

Rules before model

Predictable fields (e.g., a standard "as of" date) are caught by regex first; only genuine exceptions reach the model.

Cheap model first, escalate on doubt

Run the least expensive adequate tier by default; route only low-confidence extractions to a stronger, pricier model.

Deterministic downstream

Trend detection and manager comparison are arithmetic over structured fields — the decision tree's "use SQL" verdict, which also happens to cost nothing per query.

Provider is a setting

The highlighted node makes model choice a config value, so the team can move to whatever gives the best accuracy-per-dollar without touching the pipeline.

Scoped prompts

Send only the relevant extracted text span, not whole documents, into the model — fewer input tokens per call.

Order-of-magnitude

At a portfolio receiving tens of new documents per week, with one scoped extraction per document, inference sits in the low single-dollars per month regardless of how many times the team queries the resulting dashboard. The expensive mistake to avoid is calling a model on every poll or every dashboard view — which the extract-once design specifically prevents.

Sequence

Build phases

B1

Compliance path decided

Resolve which LLM access path is policy-compliant (the gate above) before any document text leaves the archive. Blocks everything after it. Run this review in parallel with building Architecture A so it isn't the thing you start last.

B2

Structured extraction pipeline

Deterministic text/table extraction → model extraction at the configurable node → confidence scoring → human-review queue → warehouse. Ship on a small, known-format subset of GPs first.

B3

Trend engine

Deterministic queries over the warehouse: NAV trend lines, fee-vs-NAV ratios, manager-to-manager comparison. Where the "insights" the vision calls for actually surface.

B4

Narrative synthesis + digest

RAG-backed commentary across quarters, attributed per policy, folded into a weekly digest alongside Architecture A's tracker status.
